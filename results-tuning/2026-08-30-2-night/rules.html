Which tuner rules fire on real inference — and what it costs

Tuned-vs-default A/B, 30 repeats per arm per model, SGLang TP=8 on one MI355X node (amd-mi355x-5, 2026-08-30/31). Tuned arm = DN tuner plugin + all_reduce_1n.final.conf (8 rules); default arm has no plugin. Bench: ISL 512 / OSL 512 / concurrency 32 / 128 prompts, MSCCL off, custom all-reduce off. Two run modes: detect (per-op tuner logging on — source of the hit histograms below) and quiet (per-op logging off in both arms — source of all performance verdicts).

UPDATE 2026-08-31 — the regression was the logging, not the rules

The tuner plugin writes a log line for every consultation (matched or not) when the TUNING debug topic is on — 32–213M lines per run, written mid-benchmark, only in the tuned arm. Reruns with per-op logging off in both arms (NCCL_DEBUG_SUBSYS=INIT,ENV) change every finished verdict: models whose dominant size has a rule (llama8b, qwen30b) move to parity-or-slightly-ahead; gpt-oss — whose dominant sizes match no rule — keeps a small real loss (−0.5%), the honest cost of running the tuner with no coverage.

Reading the data: with concurrency 32, steady-state decode does one all_reduce per layer per step over the whole batch: 32 tokens × hidden_size × 2 B. That single size carries ~98% of hits for llama8b and qwen235b (262144 B → R6) and for qwen30b (131072 B → top edge of range rule R5). Single-token (ramp-up/drain) decode and 16 K-token prefill chunks make up the rest. gpt-oss (hidden 2880) emits 5760 B decode and 184320 B batched decode — neither matches any rule; only its prefill chunks (k×5760, k=12–22) fall into R5's 64–128 K range. Its logged-run −1.7% is now explained by the logging confound below (the plugin logged every consultation, and gpt-oss consults millions of times even when almost nothing matches).
The logging confound (found 2026-08-31 morning): the plugin logs one line per consultation — matched or not — under debug topic TUNING. A no-R6 ablation arm held 212,824,296 DN-TUNER lines in 22 reps with only 521,040 "Applied": the tuned arm was paying a mid-benchmark write tax the default arm never paid. Quiet reruns (topic off, both arms) flip llama8b from −2.8% to +0.7% and qwen30b from −1.8% to +0.7% (individually p≈0.11/0.055 — parity or slightly ahead). Detect-which-rules-fire and measure-performance are now separate run modes: 1 logged rep for the histogram, quiet 30-rep pairs for timing.
