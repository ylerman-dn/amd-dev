The GPU-107 tuning tool: what it does, how the pieces connect, and why it is built this way

State 2026-09-15. Code: tools/rccl-sweep/ (one flat directory, 17 scripts, ~6300 lines of Python + 3 bash drivers) and the tuner plugin dn/dn-tuner/. Everything runs on the allocated cluster node inside the SGLang image; the dev VM only orchestrates over ssh. Supersedes the 2026-09-07 version of this page.

In 30 seconds. RCCL picks an algorithm, a protocol and a channel count for every collective call from a built-in cost model. A tuner conf is a table of rules ("all_reduce, 128 KB..256 KB, 8 ranks, 1 node: use tree/ll/64 channels") that overrides that choice. The tool does two things: Process A finds rules that beat RCCL's default with rccl-tests and proves each one with an A/B (rccl_tune.py end to end); Process B loads the resulting conf into a live SGLang server and measures whether tokens per second move (infer_paired.sh + infer_score.py). Every number that survives is tied to a raw log in results-tuning/<date>-N-<name>/ and a row in RUNLOG.md.

2. Process B: does the conf move a real model?

chain_template.sh in its results dir strings detect → pass 1 → pass 2 (reversed order) → fetch/score, with receipts per server. Runs unattended under Slurm for hours. Message sizes are workload-determined: decode all_reduce = concurrency x hidden x 2 B; prefill = chunk tokens x hidden x 2 B. Traffic modes are how we choose the size, not a flag.

4. Design choices: what we considered, what we chose, why

questionoptions consideredchosenwhy (evidence)
Where to run the benchmarkbare metal with the team's RCCL fork (original tool) · inside the SGLang container with stock RCCLcontainer, defaultonly the container's numbers transfer to deployment: the fork measured a different library, channel policy and launch regime (2026-09-03-2-stackcmp). Parity check tool vs hand harness: 512M 390.5 vs 390.5 GB/s.
How to search the spacefull grid · Optuna (TPE) · random · racing/adaptiveracing searchone run reports all 18 sizes, so cheap anchor sketches carry most of the information; racing found the grid winner at 235 of 236 sizes with ~20% fewer runs and stops by itself. Optuna needs a huge space and a single objective; here 810 proposals contained 788 repeats and it missed winners in 2-7 of 10 seeds (details).
Which winner per sizemax busbw · fewest channels within a tolerancefewest channels within 0.5%busbw ties are common; fewer channels means fewer CUs taken from the model. Tolerance is a measurement parameter and lives in the tool policy.
Trust what was requested?trust NCCL_ALGO/PROTO env and -A 1 · read the executed line from debug logsdebug logsRCCL substitutes silently (LL128 and tree/simple are IGNORE on this node; tree only honoured for all_reduce), and -A 1 reports 56 channels where 222 ran (findings/01, 09, 10).
Logging during measurementnone · INFO to stdout · INFO to a per-rank fileper-rank file, always, both armsINFO on stdout costs up to 4% at small sizes; to a file -0.06% mean. Compared runs must share the logging config (2026-08-03-5-lognoise).
How to prove a rulecompare medians · A/B with a statistical gateinterleaved A/B, P(sup) ≥ 0.95, gain > 2%, landmine < 2%node speed drifts ~1%/h and single repeats show transient dips; a sequential 30-rep block once produced a fake +2% (p = 1e-4) for a no-op arm. Interleaving cancels drift; the landmine check catches a range that helps at 128K and hurts at 200K.
Allocation policysalloc per step · one held allocationhold for the whole run, release on exita bare srun releases nodes the moment it ends; per-step booking lost nodes to co-tenants and broke comparability.
Where outputs go/opt/shared (NFS) · node local disknode /data/ylerman, then copied to the repothe container runs as root; NFS root_squash refused the debug-file writes, INFO spilled to stdout and the parser lost every row (sanity-check-1).
In-model A/B formone server per arm · one server, conf swapped between repsone server + hot-reload pluginsame minutes for every arm, no server restarts, drift cancels by construction. One server per arm kept for what cannot share (no plugin, other env).
Detect vs timealways log rule hits · separate 1-rep detect runseparate detectTUNING logging writes millions of lines mid-benchmark and produced fake 1.8-2.8% regressions.
Delivery formatplugin .so + conf · conf onlyconf (plugin optional)RCCL 2.30's built-in CSV tuner reads the same file and gave identical rule counts and tok/s within 0.5% (campaign D). The plugin remains useful for hot-reload searches.
Where the numbers livetool output dir · dated results dirs + RUNLOGresults-tuning/<date>-N-<name>/ + one RUNLOG row per runa run that is not in RUNLOG did not happen; the node list column is what keeps runs comparable months later.

5. What we could still do, and what the tool cannot reach

Could do with the tool as is. Multi-node campaigns (2-5 nodes: the tuner is fully visible there, DDA and AITER are single-node only; our 2n-5n rules validated at +11..+36% for all_reduce on RCCL 2.27.7 and need re-deriving on 2.30.4). Broadcast and reduce on 1 node (no DDA path; +150% rules exist but nothing in inference calls them hot). Re-running Process A on the rocm10 image with RCCL_DDA_ENABLE=0 to refresh the classic-path rules.

Could do with small additions. An env-var sweep (NCCL_BUFFSIZE, NCCL_NTHREADS, WarpSpeed knobs) to test whether ring/simple at 128M..2G can exceed its 390 GB/s; the deliverable would be env settings, not a conf. A multi-node in-model driver (SGLang --nnodes 2).

Cannot reach, by construction. Anything RCCL decides before the cost model: DDA below 64 MiB on 1 node, and SGLang's own AITER all-reduce below 64 MiB. Above 64 MiB the default was already the optimum in every dimension a tuner controls (night 2026-09-14). alltoall (p2p path, tuner never consulted). Kernel internals such as chunk pipelining.

Known gaps in the tool. todo rccl_tune.py assumes the search runs from the first booked node over ssh; the flat-grid path (rccl_sweep.py + ab_run.py) is what the September campaigns used. todo infer_hitmap.py does not recognise the built-in CSV tuner's log line (no collType=), so it reports 0 hits for that arm. human PLAN.md, RUNLOG rows, receipts review and the copy from node to repo are still manual steps; the consistency risk sits there.
